# Private worker boundary contract

This contract implements the approved runtime design. It is internal: it must never be mounted on public REST, MCP or A2A listeners. Supervisor, checkpoint, adapter and private broker implementations share these fields. B5 acceptance remains pending.

## Transport and authority

Each worker receives only its own short-lived run capability, broker URL, non-secret approved provider identity/model/destination, read-only inputs and an isolated workspace. Broker capability binds run, original/current executor generation and expiry. Every operation is checked against the immutable owner-approved plan and durable ledger. SDK and transport retries are disabled. The worker has no provider, database, S3, Docker or owner credential.

POST /effects accepts the exact OperationRequest. Committed result bytes are obtained by GET /effects/{operation_id}/result with the same run capability. This route verifies run/project/operation, generation and committed state, then reads the authoritative immutable ObjectRef through typed storage. It never accepts an arbitrary object key, URL, credential, header or ObjectRef. Unknown and denied operations do not expose bytes. Replay fingerprints exclude the new executor generation but retain the immutable approved request and reservation; the current capability must still pass generation fencing. Responses have a bounded size and canonical binary content type; the adapter validates the effect-specific JSON schema.

POST /control/boundary accepts {schema_version:1, boundary_id:UUID, expected_checkpoint_revision:nonnegative integer, context:RuntimeContextV1, workspace:[{path:string, sha256:64 lowercase hex, size:nonnegative integer, data_base64:string}]}. It records a schema-validated quiescent context and bounded relative workspace snapshot for that capability. Canonical context is at most1MiB; decoded workspace at most64MiB, at most1024 regular files, each at most20MiB with normalized path at most240 UTF-8 bytes. The transport body is limited to90MiB while streaming, before JSON parsing. All declared sizes/hashes must match decoded bytes; invalid base64, nesting deeper than16 and unexpected fields fail closed. No worker-supplied host path is accepted: the trusted controller materializes validated files in a dedicated staging directory and calls checkpoints.capture on that directory. Ack is {schema_version:1, boundary_id:UUID, checkpoint_id:UUID, checkpoint_revision:positive integer, manifest:CheckpointManifest}. A successful acknowledgement means PostgreSQL checkpoint+storage references are durable, not merely written in the worker. CheckpointManifest.revision is the checkpoint sequence; RuntimeContextV1.revision is the captured run revision. They are separate counters. Under a run-row lock, the expected checkpoint revision must equal the latest committed sequence. The boundary UUID and canonical payload digest are recorded in PostgreSQL with a unique run/boundary binding; an identical retry after commit/lost reply returns the same ack, while changed bytes, stale generation or a stale expectation for a new boundary are rejected. The adapter must receive this acknowledgement before a new external effect is dispatched. No checkpoint may serialize an in-flight local tool or transport as completed. A worker failure after an effect commit but before another boundary replays the identical recorded operation identity and obtains committed bytes, without new dispatch.

## Canonical context version 1

Context is UTF-8 JSON, bounded by the approved context limit, with no pickle, executable object, credential or absolute workspace path. Required fields: schema_version, run_id, project_id, generation, revision, input_snapshot_digest, plan_digest, runtime_commit, image_digest, skills_digest, environment_digest, provider_id, provider_endpoint, model, turn_id, system_prompt, messages, compacted_context, todo, boundary, pending_assistant, operation_mappings and operation_sequence. Saved context generation is immutable historical evidence; after verified restore, supervisor constructs an effective bootstrap with the current fenced generation and the original checkpoint identity/digest. The immutable checkpoint bytes are never edited. Ledger-original request generations remain authoritative for inactivity proof. Supervisor derives and checks authoritative immutable identity/digests; worker fields cannot change plan/provider allowance.

`budget_remaining_tokens` (ADR-012) is an optional, trusted, per-generation budget snapshot: `max(0, runs.token_limit - usage_tokens - reserved_tokens)` read from the run ledger, so owner extensions take effect without changing the immutable approved plan or plan digest. Only the server sets it. `supervisor.start` overwrites whatever the bootstrap factory supplied, `WorkerController.bootstrap_context` rebinds it on every continuation, and `boundary` stores the ledger value in the checkpoint. A worker value is never trusted or persisted. The field is additive, so `schema_version` stays 1. Checkpoints captured before ADR-012 parse as null and are rebound at bootstrap; a worker that receives null fails closed before any I/O. The snapshot is advisory. The worker's output limit is `min(requested or 2048, 2048, snapshot - this generation's charges - (serialized input + 64))`. Charges are the full reservation until commit, then the reported usage, while unknown/denied operations keep their full reservation. The input-reserve formula is shared with broker validation (`model_payload.llm_input_reserve`). Explicit limits above the allowance are clamped. If no allowance of at least 1 remains, the worker sends the unclamped request; the broker's atomic reservation check then records the owner budget wait (`budget_exhausted`, no provider call), and the worker exits with code 0 only when that wait ended the turn (pinned Hermes returns a failed turn dict, or a raised exception chains to `BudgetExhausted`), no effect of the generation is unresolved and no native tool batch is pending. The broker remains authoritative on every call.

Known limit: a request rejected this way is journaled (`before_model`), and recovery replays journaled requests exactly. After the owner extends, the replay therefore needs at least its input reserve + its output limit (up to 2048) minus the remaining budget. An extension smaller than that records another budget wait, so the owner may need to extend twice. This is bounded and never resends or double-spends. Follow-up options: put the required amount in the decision payload, or have bootstrap resize a trailing mapping that has no operations row (provably never sent).

messages retains actual Chat Completions role/content/name/tool_call_id/tool_calls data, including nullable assistant content, original raw function arguments and original tool-call IDs. The main conversation, compacted context and exact system prompt are restored together. todo retains native task IDs/content/status/parent and snapshot revision. boundary names the durable continuation point: before_model, model_committed, before_tool, tool_committed or final. pending_assistant is null or {turn_id:UUID,message_index:nonnegative integer,next_tool_index:nonnegative integer,applied_tool_ids?:[{raw_id,applied_id}]}. It points to the actual assistant message when tools remain to be applied. Ordered unique original tool-call IDs are preserved; next_tool_index cannot exceed the ordered calls. Completed prefixes must match recorded tool messages and committed ledger results; unfinished suffixes retain raw arguments. operation_mappings is a bounded list of {operation_id,turn_id,purpose:model|compression|tool,model_sequence:integer|null,tool_call_id:string|null,request:OperationRequest,payload_hash:sha256}. Exactly the relevant model sequence or original tool-call ID is present. Effect identities and operation IDs are unique; the canonical request hash excludes only executor generation. It binds persisted turn/tool-call identities to stable broker operation IDs before dispatch; operation_sequence provides the next bounded model-call slot. Controller validates existing mappings against the authoritative ledger and retains only the active continuation window, rather than duplicating every historic LLM payload. Todo entries are {id,content,status:pending|in_progress|completed|cancelled,parent?} inside {todos,revision}; native bounds are 256 entries and 4000 content characters, with a platform bound of 200 characters for IDs/parents. Compacted state preserves native nullable summary flags and the 2000-token positive micro-compaction threshold default; compression count and the active compressed messages/system prompt are restored together. Environment digest links the exact approved immutable package manifest. Compression uses the same broker accounting/identity mechanism. Deterministic local tools have no external OperationRequest: their raw tool-call IDs, completed tool messages, Todo state and workspace boundary identify continuation. External tool mappings must reference an actually issued call.

Recovery first reconciles every recorded effect. Committed model bytes reconstruct its actual assistant message; committed tool bytes reconstruct its actual tool message with the original tool_call_id. Unknown outcomes wait for owner resolution and retain reservation. Unfinished deterministic local work can resume in the workspace. After pending tools are reconstructed, a continuation turn is recorded before invoking the upstream turn entrypoint. Repeating the original user prompt as recovery is forbidden. The saved context must be sufficient without ambient HOME, source-checkout instructions, memory, soul or background review.

## Workspace and checkpoint verification

CheckpointManifest.workspace ObjectRefs are accompanied by a path manifest inside the verified context: a bounded list of normalized relative POSIX paths, byte sizes and SHA256 values. Reject absolute paths, traversal, symlinks, devices, hardlinks and duplicate/conflicting paths. Objects, manifests and extraction references use the same database session and shared object advisory lock through the durable checkpoint reference commit. Context and workspace hash/size/reference validation precedes restoration. Supervisor constructs a verified bootstrap bundle containing context bytes and normalized workspace files, with read-only approval/input/skill metadata. The immutable worker bootstrap waits for the trusted network-readiness signal, validates the bundle, imports the upstream runtime from immutable source cwd/PYTHONPATH with private HOME/HERMES_HOME already set, and only then installs/enters the restored isolated workspace. No upstream import/tool executes before fencing and firewall installation. Corruption fails closed and never dispatches a model/tool.

## Supervisor and dispatch quiescence

Lease expiry is a fencing signal, never proof that broker I/O stopped. supervisor must stop/reconcile the previous worker and owned dispatch executor before renewing authority. Broker's trusted dispatch_is_inactive(run_id, operation_id, original_dispatch_generation) callback defaults false; only authoritative executor termination/fencing proof can return true after a crash. Durable executor identity binds run, operation, original dispatch generation and supervisor process/container incarnation. Worker B owns fencing/reaping both the worker and broker dispatch executor. The broker treats its entire live transport/persistence/ledger pipeline as active, even after socket completion; reconciliation cannot race that pipeline into unknown or lose known usage. After supervisor restart the callback remains false until that identity is reconciled against the owned executor; killing only the worker is insufficient. Local executor death proves inactivity, never remote success/failure, so unknown reservations remain. Public clients, worker payloads, callbacks based solely on lease timestamps and new generations cannot assert inactivity. Known local transport completion is recorded conservatively. Owner retry uses the broker's linked retry request and a new operation identity/allowance; the original unresolved reservation remains retained.

Workers use per-run internal bridges and a numeric private broker IP/port. Trusted supervisor installs IPv4/IPv6 default-deny OUTPUT in that worker namespace before releasing the immutable readiness barrier; permit only broker TCP and required return traffic, reject Docker embedded DNS as well as external DNS. Workers have no NET_ADMIN. Rules and namespace operations remain scoped to the owned test VM, never shared Docker/macOS firewalls. Broker is a dedicated endpoint with no generic CONNECT/proxy/URL route. Actual network and hard resource limits are tested with containers on the owned fixed engine. No network simulation, skipped unsupported quota, fake upstream state seam or in-memory-only recovery can satisfy B5.

## Bootstrap metadata and generation rebinding

The immutable bootstrap requires metadata.json with {schema_version:1,checkpoint_revision:nonnegative integer}. Fresh runs explicitly use0; restored runs use the verified selected manifest sequence. RuntimeContextV1.revision remains the captured run revision. The adapter advances its checkpoint sequence only after the corresponding acknowledgement. PendingAssistant.applied_tool_ids contains ordered {raw_id,applied_id} pairs for actual native execution, preserving raw wire IDs/arguments. A trusted effective-bootstrap factory rebinds only requests absent from the journal to the new generation; requests already journaled retain their ledger-original generation. Original checkpoint bytes remain unchanged.

Native timestamp metadata is stored separately as native_message_metadata:[{message_index,timestamp}], indexed against canonical primary context.messages. Only approved wire fields are serialized to model APIs; timestamps retain exact finite nonnegative native numeric seconds (integer/float) or validated bounded ISO text, without conversion, while disabled native-session database UIDs are omitted. API-temporary system insertion/user merging and compression summarizer prompts never define durable primary-history indices. Hermes one-total-attempt policy differs from SDK zero-retries; native auxiliary retry/fallback paths must be separately disabled.

`current_turn_user_index` optionally identifies the exact current primary user row, validated against canonical history. The adapter records/reanchors it after compaction; continuation without a proven anchor fails closed. `native_turn_timestamp` preserves the separate native admission clock losslessly; it is not inferred from message metadata. Optional fields preserve old snapshot representation compatibility, not guaranteed native resumability.

The private app bounds incoming POST /effects bodies to 2 MiB of actual streamed bytes before JSON or Pydantic parsing. Content-Length is never accepted as proof of size. Oversize streams receive 413 without dispatch or consuming their remaining body; an exactly bounded valid request retains the existing broker authorization/journal semantics.

Tool function descriptions retain their exact text with a bounded 2048-character limit, accommodating the pinned runtime's 1060-character discovery description. The existing total tool-definition byte budget and reservation accounting still include all description bytes; the adapter must not truncate or rewrite tool wording to fit the wire profile.
